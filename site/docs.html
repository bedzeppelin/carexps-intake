The flow

A patient fills in the form on a tablet at the front desk, or on their own phone. When they press submit, this happens:

  1. The form builds one submission object Every answer is collected into a single JSON object. This object is the only source of truth — the PDF, the CSV, the clinical note and the FHIR bundle are all generated from it, so they cannot disagree with each other.
  2. It is sent to the clinic PC The tablet posts it over the clinic network. The PC writes it to a local queue and confirms it to disk before doing anything else, so a power cut cannot lose a form.
  3. The PC renders the PDF and files it A PDF laid out like the paper intake form is written into the clinic's OneDrive folder. Only once that file is confirmed on disk does the tablet get a success response and clear the patient's answers.
  4. The tablet thanks the patient and clears itself The patient sees a confirmation and a short countdown, then the form returns to the start for the next person. There is nothing for them to open, download or go back to — the completed form is the clinic's from this point on.
  5. It appears in the staff console The front desk sees the form in the list, can open it, download it in any format, or delete it.

On this review site, steps 2 and 3 run in your browser instead of on a clinic PC — there is no server here. A form you submit is held in your browser's own storage and appears in the console immediately. Everything after that point is the real code: the same exporters, the same PDF layout, the same filenames.

Try it: open the patient form, fill it in, and it will be waiting in the staff console.

Export formats

Four representations of the same submission. All four are available for a single form, and any of them can be produced for a whole day at once.

FormatExtensionWhat it is for
PDF.pdf A copy of the completed intake form, laid out like the paper original, including the patient's signature. This is the document to attach to a chart.
CSV.csv One row per form, 48 fixed columns. For a spreadsheet or a bulk import. UTF-8 with a byte-order mark so Excel opens accented names correctly.
JSON.json The complete submission object, including everything the CSV flattens or omits.
Clinical note.txt Plain text, laid out for an encounter note. This is what staff paste into a chart today.
FHIR R4.fhir.json A FHIR R4 collection bundle — Patient, Encounter, Condition, AllergyIntolerance, MedicationStatement, Procedure, Observation and Consent resources.

The CSV column order is fixed

Columns are declared explicitly rather than derived from the data, so the header is identical for every export. A field a particular form did not collect comes through as an empty cell rather than shifting the columns — which means a file with a quick check-in and a full registration in it still lines up.

Two form types

A returning patient can use a quick check-in, which collects identity and reason for visit only. A first-time patient does a full registration. A full registration also asks four extra sections — medical history, past surgeries, medications and family history — but only if the patient is signing up for a family doctor.

File naming

Every exported file for a single form uses the same stem:

4821567390AB_Mitchell_Sarah_2026-08-31_a7f3c891.pdf
└──────────┘ └─────────────┘ └────────┘ └──────┘
 health no.   last_first      date       reference

The health number comes first so files sort by patient, and so the number a chart is matched on is visible without opening anything. The trailing reference is the first eight characters of the submission id, which keeps two forms for the same patient on the same day from colliding.

A form submitted without a health number gets NOHCN in that position, so those stand out in a folder listing rather than producing a file that looks like it has a number.

The daily batch

At the end of the day, from the staff console:

  1. Tick the forms to export, or use Select all.
  2. Choose Download PDFs for the documents alone, Download CSV for a single spreadsheet with one row per form, or Download everything.
  3. Download everything produces one .zip containing a PDF, a JSON file and a clinical note for each form, plus a single CSV covering all of them.

Selecting a single form and choosing Download PDFs gives a plain PDF rather than an archive, so a one-off export does not need unzipping.

Clearing forms

Each row has its own Delete, and ticking several and pressing Delete in the toolbar removes them together. Both ask for confirmation first and name what is going. Once a day's forms have been exported and filed, deleting them keeps the list to what still needs handling.
