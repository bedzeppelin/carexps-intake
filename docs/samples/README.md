# Sample exports

Every file here is **synthetic test data** — invented names, invented health
numbers, invented addresses. No real patient information is present.

They are generated by the app's own exporters rather than written by hand, so
they cannot drift from the shipping code:

```bash
node docs/samples/generate.mjs
```

| File | What it is |
|---|---|
| `full-registration.json` | The canonical submission object. Every other file here is derived from it. |
| `full-registration.csv` | One row, 48 fixed columns, UTF-8 with a BOM so Excel on Windows opens accented names correctly. |
| `full-registration.fhir.json` | FHIR R4 collection bundle — 19 resources. |
| `full-registration.txt` | The plain-text clinical note. This is what staff select and paste into Alembico today. |
| `quick-checkin.json`, `.csv`, `.txt` | The reduced returning-patient shape: identity and reason for visit only. |
| `batch.csv` | Three submissions, one row each — the shape a bulk loader wants. |

## What the samples cover

The three fixtures were chosen to exercise the shapes that differ, not to be
representative of a typical day:

- **`full-registration`** — first-time patient who opted into a family chart, so
  it carries all four conditional sections (medical history, surgeries,
  medications, family history), a drug allergy, a non-drug allergy with a
  reaction, and both emergency contacts.
- **`no-family-doctor`** (inside `batch.csv`) — full registration where the
  patient declined a family chart, so the four conditional sections are absent
  entirely. Also carries `noKnownDrugAllergies: true`, which is an explicit
  answer rather than an empty list.
- **`quick-checkin`** — returning patient. Carries `meta`, `checkin` and a
  reduced `visit` only. No `patient`, no `consent`. Note the health number here
  has no version code, which some older cards genuinely lack.

## One thing that is omitted

`consent.signaturePng` is a `data:image/png;base64` URI of roughly 20–30 KB in a
real submission. It is left out of these samples for length, and out of the CSV
entirely. If you need to see one, ask.

See [`../ALEMBICO-INTEGRATION.md`](../ALEMBICO-INTEGRATION.md) for what the
fields mean and what we need from Alembico.
